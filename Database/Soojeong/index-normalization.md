## DDL / DML / DCL

### DDL (Data Definition Language)

DDL은 데이터베이스의 구조(스키마)를 정의하는 언어이다.

즉, 테이블이나 데이터베이스의 뼈대 자체를 만드는 명령어이다.

**주요 명령어**

- `CREATE` : 테이블, DB 생성
- `ALTER` : 테이블 구조 수정
- `DROP` : 객체 삭제
- `TRUNCATE` : 테이블 전체 데이터 삭제 (구조는 유지)

**특징**

- 자동 커밋(Auto Commit)
- 롤백 불가능
- 데이터가 아니라 구조를 변경

### DML (Data Manipulation Language)

DML은 데이터를 조회하고 조작하는 언어이다.

테이블 안에 들어있는 데이터 자체를 다루는 명령어이다.

**주요 명령어**

- `SELECT` : 조회
- `INSERT` : 삽입
- `UPDATE` : 수정
- `DELETE` : 삭제

**특징**

- 트랜잭션 적용 대상
- `COMMIT`, `ROLLBACK` 가능
- 실제 데이터를 변경

### DCL (Data Control Language)

DCL은 데이터 접근 권한을 제어하는 언어이다.

**주요 명령어**

- `GRANT` : 권한 부여
- `REVOKE` : 권한 회수

**목적**

- 보안 유지
- 사용자별 접근 제어




## 인덱스(Index)

### 인덱스란?

인덱스는 데이터를 빠르게 찾기 위한 자료구조이다.

책의 “목차” 또는 “색인”과 같은 개념이다.

테이블 전체를 스캔하지 않고도 빠르게 원하는 데이터를 찾을 수 있다.

### Cluster 인덱스 (Clustered Index)

Cluster 인덱스는 데이터 자체를 정렬하여 저장하는 인덱스이다.

- 테이블당 1개만 존재
- 실제 데이터가 인덱스 순서에 맞춰 물리적으로 정렬됨
- 보통 PK(Primary Key)에 자동 생성

→ 책 내용이 페이지 순서대로 정렬되어 있는 것과 같다.

**장점**

- 범위 검색에 매우 빠름
- 정렬된 데이터 조회에 효율적

### Non-Cluster 인덱스 (보조 인덱스)

Non-Cluster 인덱스는 데이터 위치를 가리키는 별도의 인덱스이다.

- 실제 데이터는 정렬되지 않음
- 인덱스에 포인터가 저장됨
- 여러 개 생성 가능

→ 책 뒤에 있는 색인(Index) 페이지와 같다.

### 멀티 인덱스 (Composite Index)

두 개 이상의 컬럼을 묶어 만든 인덱스이다.

`INDEX (name, age)`

**특징**

- 왼쪽부터 사용됨 (Left-most Rule)
- `(name, age)` 인덱스는 `name` 단독 검색 가능
- 하지만 `age` 단독 검색은 비효율적

### 커버링 인덱스 (Covering Index)

조회에 필요한 모든 컬럼을 인덱스가 포함하는 경우를 말한다.

즉, 테이블을 보지 않고 인덱스만으로 결과를 반환할 수 있는 상태이다. 

**장점**

- 성능 매우 빠름
- 디스크 I/O 감소

### B트리 (B-Tree)

대부분의 DB 인덱스는 B-Tree 구조로 구성된다.

**특징**

- 균형 트리 구조
- 항상 정렬된 상태 유지
- 검색, 삽입, 삭제 시간복잡도: O(log N)

**왜 빠를까 ?**

루트 → 브랜치 → 리프 노드로 이동하며 탐색 범위를 계속 절반씩 줄이기 때문이다.





## 정규화, 반정규화

### 정규화(Normalization)

정규화는 데이터의 중복을 제거하고 이상현상을 방지하기 위한 설계 기법이다.

**목적**

- 데이터 중복 제거
- 무결성 유지
- 삽입/삭제/갱신 이상 방지

**단계**

- **1NF (제1정규형) : 원자값 확보**
    - 모든 도메인이 원자값(Atomic Value)으로만 구성되어야 한다. 한 칸에 여러 개의 값이 들어가지 않도록 분리하는 단계이다.
- **2NF (제2정규형) : 부분 함수 종속 제거**
    - 기본키가 복합키(여러 컬럼의 조합)일 때, 기본키의 일부분에만 종속되는 컬럼을 분리한다. 완전 함수 종속을 만족해야 한다.
- **3NF (제3정규형) : 이행 함수 종속 제거**
    - 기본키가 아닌 컬럼 간에 종속 관계가 존재하는 것을 분리한다. 즉, A->B, B->C 관계가 성립할 때 A->C가 되는 관계를 끊어내는 과정이다.
- **BCNF (보이스-코드 정규형)**
    - 모든 결정자가 후보키가 되도록 강제하여, 3차 정규화로 해결되지 않는 결정자 문제를 해결한다.
- **4NF (제4정규형) : 다치 종속 제거**
    - 독립적인 여러 다중값 관계가 한 테이블에 있지 않도록 분리하는 단계이다.
    
- **5NF (제5정규형) : 조인 종속 제거**
    - 더 작은 테이블로 쪼갰을 때 정보 손실이 없는 상태까지 분해하는 단계이다.
    

### 반정규화(Denormalization)

반정규화는 성능 향상을 위해 일부러 중복을 허용하는 설계이다.

**왜 해야할까?**

- JOIN 비용 감소
- 조회 성능 향상

**단점**

- 데이터 중복 발생
- 정합성 관리 어려움

→ 읽기 성능이 중요한 시스템에서 사용




## 커넥션 풀(Connection Pool)

커넥션 풀은 데이터베이스 연결 객체를 미리 생성해 두고 재사용하는 기술이다.

**왜 필요할까 ?**

DB 연결은 비용이 매우 크다.

1. TCP 연결
2. 인증
3. 세션 생성

매번 연결/해제를 반복하면 성능 저하 발생

**동작 방식**

1. 서버 시작 시 미리 커넥션 생성
2. 요청이 오면 풀에서 하나 빌려줌
3. 사용 후 반납
4. 재사용

**장점**

- 응답 속도 향상
- 리소스 절약
- 동시 접속자 제어 가능
